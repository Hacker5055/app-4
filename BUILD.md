# Build guide — Canary Duress Lock

## TL;DR

```bash
flutter pub get
flutter build apk --release --target-platform android-arm64
# → build/app/outputs/flutter-apk/app-release.apk
```

## 1. Toolchain

```bash
flutter --version     # 3.22+ (3.24.x recommended)
flutter doctor -v     # must show a green Android toolchain
```

Required: Flutter 3.22+, JDK 17, Android SDK Platform 34, Build-Tools 34.x, NDK (as pinned by
Flutter). Kotlin 1.9.22 and AGP 8.3.0 are pinned in `android/settings.gradle`.

`android/local.properties` is generated by the Flutter tool on first build
(`flutter.sdk`, `sdk.dir`). If you invoke Gradle directly, either create it yourself or export
`FLUTTER_ROOT` — `settings.gradle` accepts both.

## 2. Dependencies

```bash
flutter pub get
```

No code generation step is required (no build_runner, no generated Hive adapters).

## 3. Emulator / debug run

```bash
flutter devices
flutter run -d emulator-5554            # hot reload included
# or
flutter build apk --debug --target-platform android-arm64
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

The debug build ships with mock testing mode available; enable it on the lock screen.

## 4. Release APK (ARM64)

```bash
flutter clean
flutter pub get
flutter build apk --release --target-platform android-arm64
ls -lh build/app/outputs/flutter-apk/
```

`--target-platform android-arm64` embeds only `arm64-v8a` native libs — a single APK per the spec.
Add `--split-per-abi` only if you also want 32-bit output.

Gradle route:

```bash
cd android
./gradlew assembleRelease        # or ./gradlew bundleRelease for an .aab
cd ..
```

## 5. Signing

`android/app/build.gradle` falls back to the debug keystore so `assembleRelease` works out of the
box. For a shippable artifact:

```bash
keytool -genkeypair -v -keystore ~/canary-release.jks \
        -keyalg RSA -keysize 4096 -validity 10000 -alias canary

export KEYSTORE_PATH=~/canary-release.jks
export KEYSTORE_PASSWORD='…'
export KEY_ALIAS=canary
export KEY_PASSWORD='…'
flutter build apk --release --target-platform android-arm64
```

`*.jks`, `android/key.properties` and `android/local.properties` are git-ignored — never commit them.

## 6. Verify the artifact

```bash
APK=build/app/outputs/flutter-apk/app-release.apk

# ABI + package sanity
unzip -l "$APK" | grep -E 'lib/arm64-v8a'
$ANDROID_HOME/build-tools/34.0.0/aapt2 dump badging "$APK" | grep -E 'package|native-code|sdkVersion'

# privileged components present
$ANDROID_HOME/build-tools/34.0.0/aapt2 dump xmltree --file AndroidManifest.xml "$APK" \
  | grep -E 'BIND_DEVICE_ADMIN|BIND_ACCESSIBILITY_SERVICE|USE_BIOMETRIC|device_admin|accessibilityservice'

# must print nothing in release
$ANDROID_HOME/build-tools/34.0.0/aapt2 dump xmltree --file AndroidManifest.xml "$APK" | grep debuggable
```

## 7. Testing the duress flow safely

1. Install the debug APK.
2. First launch → wizard: master `123456`, duress `654321`, action *Decoy + Purge*.
3. Open **Duress configuration** → enable **Mock testing mode** (amber banner appears).
4. Lock the vault, enter `654321`.
5. The mock log lists every native call; tap **Enter decoy mode** → calculator/notes/gallery.
6. Tap the **Smart Tools** title 5× → *Exit decoy* → lock screen.
7. Unlock with `123456` — the vault is intact, because mock mode was on.
8. Turn mock mode **off** only on a device you are willing to wipe.

Physical-device checks worth doing once: `KeyStoreManager.getKeyInfo()` should report
`insideSecureHardware: true` (and `isStrongBoxBacked: true` on Pixel-class hardware).

## 8. Troubleshooting

| Symptom | Fix |
|---|---|
| `flutter.sdk not set` | run `flutter build apk` once (writes `local.properties`) or export `FLUTTER_ROOT` |
| `StrongBox not available` in logcat | expected on emulators; automatically falls back to TEE |
| Device Admin toggle does nothing | Settings → Security → Device admin apps → enable *Canary Duress Lock* |
| Wipe returns `ADMIN_NOT_ACTIVE` | same as above; admin must be activated interactively |
| Gradle can't find SDK | set `sdk.dir` in `android/local.properties` or `ANDROID_HOME` |
| Build fails on `namespace`/`package` | ensure no `package=` attribute in `AndroidManifest.xml` (AGP 8) |

## 9. CI (GitHub Actions)

```yaml
name: release-apk
on: [push]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '17' }
      - uses: subosito/flutter-action@v2
        with: { flutter-version: '3.24.5', channel: stable, cache: true }
      - run: flutter pub get
      - run: flutter analyze
      - run: flutter test
      - run: flutter build apk --release --target-platform android-arm64
        env:
          KEYSTORE_PATH: ${{ github.workspace }}/canary.jks
          KEYSTORE_PASSWORD: ${{ secrets.KEYSTORE_PASSWORD }}
          KEY_ALIAS: canary
          KEY_PASSWORD: ${{ secrets.KEY_PASSWORD }}
      - uses: actions/upload-artifact@v4
        with: { name: canary-arm64-apk, path: build/app/outputs/flutter-apk/*.apk }
```

## 10. Native APK module (no Flutter toolchain required)

If you only need an installable APK — or the Flutter engine artifacts are unreachable from your
network — `native/` builds the same app from Kotlin sources with framework views only.

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_JAR=$ANDROID_HOME/platforms/android-34/android.jar
export BUILD_TOOLS=$ANDROID_HOME/build-tools/34.0.0
export KOTLINC=/path/to/kotlin/bin/kotlinc

cd native && ./build.sh
# → native/build/CanaryDuressLock-v1.0.0.apk   (signed, v1+v2+v3)
```

Pipeline: `aapt2 compile` → `aapt2 link` → `kotlinc` → `d8 --min-api 23` → `zip classes.dex` →
`zipalign -p 4` → `apksigner sign`. No Gradle, no AGP, no Flutter engine, no AndroidX.

Prebuilt artifact in this repo: `dist/CanaryDuressLock-v1.0.0.apk`
(`sha256 dba33db328a012fcb449aeceff2f8c6bb4f1dbe2cd597a75da8c67a319350fba`).

Details and file map: [native/README.md](native/README.md).
